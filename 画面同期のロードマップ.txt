■ レベル1：jQueryのチャット（基礎）
==================================================

【理解するべき点】

・jQueryとは
　HTMLに include して使えるフロントエンド向けフレームワーク。

・セレクタの概念
　$("#aaa") → id セレクタ
　$(".aaa") → class セレクタ
　どのHTML要素を操作するかを指定する考え方。

・clickの概念
　「何をクリックしたら、何が起きるか」を記述する。
　イベント駆動の基本。

・LocalStorageの概念
　ブラウザ内にデータを保存できる仕組み。
　MySQLなどのDBを用意すると無駄に壮大なため、
　LocalStorageを扱えるようになると今後かなり便利。

・LocalStorageを使ったチャットシステムの構築
　LocalStorage経由でメッセージを保存・取得。
　疑似的なチャットのやり取りが可能。

■ レベル2：画面同期が必要になる理屈
==================================================

【画面同期とは】
複数人の画面を同じ状態に保つ仕組み。
（理想的には差分が 0.00001ms も許されない世界）

チャットやリアルタイムUIでは必須の概念。

【代表例】
・Google Firebase
・Twilio Sync（過去）

【仕組みを図で考える】

仮に、
　田中さん = B
　鈴木さん = C
　Firebase = A

構造は以下のようになる。

A（Firebase）
├ B（田中）
└ C（鈴木）

・BとCは直接つながらない
・Aが更新される
・結果としてBとCが同じ状態になる

つまり、
「AをFROMとしてBとCが作られている」ため、
「Aが更新される＝全員が同期する」という仕組み。

※ 2026年時点での主流技術は流動的なため要調査。


==================================================
■ レベル3：VPS / AWSで動かせるか？
==================================================

【この段階で問われること】

・理屈は分かった
・完全な画面同期には大手APIが必要な理由も分かった
・では、それを自前インフラで動かすとどうなる？

【分岐点】

if1：動かせる（だけ）
　→ 論外

if2：動かせて赤字
　→ クエリ設計が悪いかもしれない
　→ フレームワーク選定が悪いかもしれない
　→ 設計が悪いかもしれない
　→ いずれにせよ論外

if3：動かせて黒字
　→ 無駄なトラフィックが発生しない
　→ 設計・実装を改善すれば成立する可能性がある
